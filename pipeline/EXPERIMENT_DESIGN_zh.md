# OrbBench 两组核心实验设计

## 实验一：多源数据驱动的 STM 全流程 Pipeline

### 目标

验证两点：

1. 七项任务能否通过明确的输入输出组成统一 STM Pipeline，并提升预测、预警、避碰效果及计算效率。
2. 机动、空间天气、物理属性和高精度轨道等数据是否使STM任务获得可测量的收益。

### Pipeline

```text
轨道阶段划分 ---- phase label --------+
机动事件识别 ---- maneuver label ------+-> 非合作目标轨道预测 + UQ --+
空间天气预测 ---- weather forecast ----+                              |
目标/星座演化 --- candidate priority --------------------------------+-> 碰撞预警 -> 自主避碰
                                                                                      |
                                                                                      +-> 动作后风险复核
```

| 上游任务 | 输出 | 下游用途 |
| --- | --- | --- |
| 轨道阶段划分 | 阶段标签、切换时刻 | 为不同运行阶段选择或调整轨道预测方法 |
| 机动事件识别 | 机动概率、类型、影响区间 | 机动后重置预测状态，避免继续外推旧轨迹 |
| 空间天气预测 | F10.7、Kp、Ap及扰动概率 | 修正LEO阻力和轨道误差增长 |
| 目标/星座演化 | 拥堵区域、候选对象优先级 | 缩小碰撞精筛范围 |
| 轨道预测 | 未来位置、速度和协方差 | 计算TCA、miss distance和碰撞风险 |
| 碰撞预警 | 高风险事件、风险等级和处置时间 | 生成自主避碰episode |
| 自主避碰 | 动作时刻、方向和Delta-v | 重传播动作后轨道并复核风险 |

### 实验1A：Pipeline是否有效

使用相同数据、方法和测试episode，只改变任务是否连接。

| 配置 | 说明 |
| --- | --- |
| A0 Independent | 七项任务独立运行，下游不读取上游输出 |
| A1 Chained | 七项任务按照Pipeline连接 |

比较指标：

- 轨道预测：RTN误差P50/P95、机动后误差、强扰动期间LEO误差；
- 碰撞预警：危险事件Recall、假警率、漏警率、TCA和miss-distance误差；
- 自主避碰：安全率、平均/最大Delta-v、任务轨道偏离、二次交会率；
- 计算效率：候选对数量、候选缩减率、筛查时间、端到端运行时间；
- 流程完整性：完成全流程的episode比例，以及每次预警和动作的可追溯性。

成立条件：A1在保持危险事件Recall的同时减少候选计算或假警，并提高轨道预测、预警或避碰指标。

逐条断开`phase -> prediction`、`maneuver -> prediction`、`weather -> prediction`和`evolution -> warning`，记录最终指标变化，验证每条任务连接的作用。

### 实验1B：多源数据是否有用

保持Pipeline、方法和测试episode不变，只删除一类数据。

| 配置 | 删除内容 | 重点观察指标 |
| --- | --- | --- |
| B0 Full | 不删除 | 完整OrbBench结果 |
| B1 No-maneuver | 机动信息 | 机动后轨道P95误差、预警漏报率 |
| B2 No-weather | 空间天气 | 强扰动期间LEO轨道误差、风险等级变化 |
| B3 No-physical | 质量、尺寸、面质比 | 风险排序、假警率、避碰Delta-v |
| B4 No-precise | 历史POD和运营方星历 | 轨道残差、跨目标泛化误差 |
| B5 TLE-only | 全部辅助数据 | 可支持任务数、有效episode数、预警和避碰结果 |

多源数据的价值从两方面证明：

1. 支撑范围：加入数据后新增了哪些可定义任务、有效样本和独立评价真值。
2. 性能收益：B0相较删除版本改善了对应任务指标，且报告配对差值和bootstrap 95%置信区间。

## 实验二：轨迹精度与不确定度有效性

### 目标

验证三点：

1. 质量控制和轨迹构建方法是否提高轨迹精度。
2. OrbBench不确定度是否反映真实轨道误差水平。
3. 不确定度是否改善碰撞预警和自主避碰。

### 实验2A：轨迹精度提升

在具有POD或运营方星历真值的相同对象和时间点上比较：

| 配置 | 说明 |
| --- | --- |
| C0 Raw | 原始TLE，不筛选 |
| C1 QC | 筛选或降权异常TLE，传播方法与C0相同 |
| C2 QC+Track | 使用QC和OrbBench最终连续轨迹构建方法 |

记录RTN误差P50/P90/P95、严重错误比例、传播失败率、数据覆盖损失和真实机动保留率。

成立条件：C2相较C0显著降低P95误差和严重错误比例，同时没有通过大量删除数据或真实机动获得表面提升。C0与C1用于隔离QC效果，C1与C2用于隔离轨迹构建方法的效果。

### 实验2B：不确定度能否反映真实误差

使用一组目标校准协方差，在不同目标和时间上测试。记录：

- 预测标准差与真实RTN误差的相关性；
- 不确定度分箱后的平均真实误差；
- 50%、90%、95%区间的实际覆盖率；
- Calibration Gap、NEES和NLL。

成立条件：真实误差随预测不确定度增加，标称区间接近实际覆盖率，并且在未见目标和时间上保持校准。

### 实验2C：不确定度能否改善STM任务

保持点轨道和测试事件相同，只改变风险模型。

| 配置 | 说明 |
| --- | --- |
| D0 Point | 仅使用点轨道和距离阈值 |
| D1 Fixed-UQ | 所有目标使用相同固定协方差 |
| D2 OrbBench-UQ | 使用逐目标、逐时刻的校准协方差 |

记录：

- 碰撞预警：危险事件Recall、假警率、漏警率、Recall@K、Brier Score和NLL；
- 风险变化：预警等级发生变化的事件数，以及正确和错误修正数量；
- 自主避碰：触发次数、无效避碰、漏避、安全率和总Delta-v。

成立条件：D2在相同危险事件Recall下减少假警和无效避碰，或在相同Delta-v预算下提高安全率。

## 最终需要输出的结果

1. 七任务Pipeline及输入输出关系图。
2. Independent与Chained的STM性能和效率对比表。
3. Full与各类数据删除版本的消融图。
4. Raw、QC和QC+Track的RTN误差CDF及覆盖损失表。
5. 不确定度分箱误差图和可靠性曲线。
6. Point、Fixed-UQ和OrbBench-UQ的预警及避碰结果表。

两组实验分别支撑论文的两项核心结论：多源数据和任务连接使OrbBench能够执行并改善STM全流程；质量控制提高轨迹精度，校准不确定度反映剩余误差并改善风险决策。
